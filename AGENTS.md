## Dev environment & commands

- Install dependencies: `bun install` (uses `bun.lock`; do not commit `package-lock.json`, `yarn.lock`, or `pnpm-lock.yaml`)
- Dev server (Turbopack on `http://localhost:3000`): `bun run dev`
- Production build: `bun run build`
- Start production server: `bun run start`
- Lint (ESLint 9 flat config in `eslint.config.mjs`): `bun run lint`
- Typecheck: `bunx next typegen && bunx tsc --noEmit` (`next typegen` generates `.next/types/` required by `next-env.d.ts` and `tsconfig.json` on a clean checkout)
- Tests: none configured yet (no `test` script in `package.json`)

## Conventions

- Directory layout: App Router files live at repo root in `app/` (`layout.tsx`, `page.tsx`, `globals.css`) and static assets in `public/`; there is no `src/` directory.
- Imports & TypeScript: `"strict": true` in `tsconfig.json`; `@/*` aliases the repo root (`./*`). Use `import type` for type-only imports, double quotes, semicolons, and 2-space indentation.
- Route props typing: Use the global `LayoutProps<"/...">` and `PageProps<"/...">` helpers generated by Next.js (see `app/layout.tsx`) without importing them. Dynamic `params` and `searchParams` are `Promise`s — unwrap with `await` or `React.use()`.
- Styling: Tailwind CSS v4 runs through `@tailwindcss/turbopack` in `next.config.ts` (there is no `postcss.config.*` or `tailwind.config.*`). Theme tokens and CSS variables (`--font-geist-sans`, `--font-geist-mono` from `next/font/google`) are defined via `@import "tailwindcss";` and `@theme inline` in `app/globals.css`.

## Pitfalls

- `cacheComponents: true` and `partialPrefetching: true` are active in `next.config.ts`:
  - Data fetching is dynamic by default; opt into caching explicitly with `"use cache"`, `cacheLife()`, and `cacheTag()`.
  - Route segment exports `dynamic`, `dynamicParams`, `revalidate`, `fetchCache`, `experimental_ppr`, and `runtime` (both `'nodejs'` and `'edge'`) are unsupported under `cacheComponents` and break the build.
  - `partialPrefetching: true` requires `cacheComponents: true`; disabling `cacheComponents` alone fails config validation.
  - Client navigations keep recent routes mounted inside hidden React `<Activity>` boundaries, so component state persists across back/forward navigation.
- Next.js 16 renames & deprecations: `middleware.ts` is deprecated in favor of `proxy.ts`. Check `node_modules/next/dist/docs/` before relying on Next.js 14/15 APIs.
- Generated blocks & files — do not edit by hand:
  - Keep `<!-- BEGIN:nextjs-agent-rules -->` ... `<!-- END:nextjs-agent-rules -->` intact; `next dev` overwrites edits inside those markers.
  - Do not edit `next-env.d.ts` (gitignored) or `.next/types/**`; regenerate with `bunx next typegen`.
- Bun install scripts: Bun blocks dependency lifecycle scripts unless listed in `"trustedDependencies"` in `package.json` (currently `sharp` and `unrs-resolver`, paired with `"ignoreScripts"`).
